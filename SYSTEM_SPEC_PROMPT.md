## 1. АРХИТЕКТУРА И ОБЩАЯ КОНЦЕПЦИЯ СИСТЕМЫ

Система представляет собой автомобильный медиаадаптер для головных устройств автомобилей Ford (с поддержкой шины CAN магнитол Ford Denso / Visteon). 

Система состоит из трёх компонентов:
1. **Master-контроллер (ESP32-S3):** Главный контроллер. Читает USB-флешку, управляет ЦАП, шиной CAN, питанием, сетью Wi-Fi/BLE и координирует Slave.
2. **Slave-контроллер (ESP32):** Bluetooth-приёмник. Принимает поток A2DP со смартфона, выводит звук по I2S на Master, управляется по UART от Master.
3. **Мобильное приложение (Android):** Управление плеером, плейлистом, настройками и OTA-прошивкой обоих чипов по BLE и Wi-Fi.

## 2. АППАРАТНЫЕ ИНТЕРФЕЙСЫ И ТАБЛИЦА ПИНОВ

### Межчиповое соединение (Master ESP32-S3 ↔ Slave ESP32):
| Линия / Сигнал | Пин Master (ESP32-S3) | Пин Slave (ESP32) | Описание |
| :--- | :--- | :--- | :--- |
| **I2S BCLK** | `GPIO 41` (In, Slave) | `GPIO 26` (Out, Master) | Битовая синхронизация звука |
| **I2S WS** | `GPIO 39` (In, Slave) | `GPIO 33` (Out, Master) | Выбор канала (Left/Right) |
| **I2S Data** | `GPIO 40` (In, Slave) | `GPIO 25` (Out, Master) | Поток PCM сэмплов от Bluetooth к Master |
| **UART TX ➔ RX** | `GPIO 8` (TX) | `GPIO 22` (RX) | Команды управления (0xAA) и OTA прошивка (0x55) |
| **UART RX ◄─ TX** | `GPIO 9` (RX) | `GPIO 23` (TX) | Ответы ACK/NACK, статусы, версии ПО |
| **Sleep Sync** | `GPIO 21` (Out) | `GPIO 34` (In) | HIGH = Активен, LOW = Команда уйти в Deep Sleep |
| **GND / VCC** | `GND`, `3.3V/5V` | `GND`, `3.3V/5V` | Общая земля и стабильное питание |

### Внешние подключения Master ESP32-S3:
- **CAN-шина (TWAI):** `GPIO 4` — TX, `GPIO 15` — RX (к трансиверу шины Ford). Пин RX является источником пробуждения `ext0` из Deep Sleep.
- **I2S ЦАП (PCM5102A):** `GPIO 17` — BCLK, `GPIO 18` — WS, `GPIO 16` — DOUT (Master Transmitter, 16 bit, Stereo).
- **USB-Host (флешка):** `GPIO 19` — D-, `GPIO 20` — D+ (USB OTG).
- **Кнопка отладки (BOOT):** `GPIO 0` (вход с подтяжкой к питанию).

## 3. СПЕЦИФИКАЦИЯ ПРОТОКОЛОВ

### 3.1. CAN-шина (Ford Denso / Visteon)
- **Скорость:** 125 kbps (тайминги TWAI ESP-IDF).
- **ID сообщений:** `0x2D5`.
- **Логика байтов:** При условии `(data[0] & 0xF0) == 0x00`:
  - `data[1] & 0xF0 == 0x40` (кроме 0x49) ➔ **NEXT TRACK**.
  - `data[1] & 0xF0 == 0x80` (кроме 0x89) ➔ **PREV TRACK**.
  - `data[1] & 0xF0 == 0x10` (кроме 0x19) ➔ **MODE SWITCH** (USB <-> Bluetooth).
- **Антидребезг (Debounce):** Обязательная проверка времени между командами (не менее 200–300 мс).

### 3.2. Межчиповый протокол UART (UART1, 115200 бод, 8N1)
- **Команды управления (Префикс `0xAA`):**
  - `[0xAA][0x04]` — Следующий трек (Slave отправляет AVRCP Next на телефон).
  - `[0xAA][0x05]` — Предыдущий трек (Slave отправляет AVRCP Prev на телефон).
  - `[0xAA][0x06]` — Запрос версии Slave. Slave возвращает структуру с датами сборки.
- **Протокол OTA-прошивки Slave (Префикс `0x55`):**
  - Старт: `[0x55][0x01][size: 4B LE][crc32: 4B LE]` ➔ Slave вызывает `esp_ota_begin()`, отвечает `0x55 0x06` (ACK).
  - Блок: `[0x55][0x02][block_num: 2B][data_len: 1B][data: <=240B][crc16: 2B]` ➔ Проверка CRC16 Modbus, запись во flash (`esp_ota_write()`), ответ ACK/NACK.
  - Конец: `[0x55][0x03][final_crc32: 4B]` ➔ Проверка общей CRC32, `esp_ota_set_boot_partition()`, ответ `0x55 0x09` (COMPLETE) и перезагрузка.

### 3.3. BLE GATT Сервер Master контроллера
- **Имя устройства:** `ESP32_MP3_Player`
- **Service UUID:** `11000000-0000-1000-8000-00805f9b34fb`
- **Характеристики:**
  - `11010000-...` (**Command**, Write): строковые команды `play`, `pause`, `next`, `prev`, `track:<id>`, `seek:<ms>`, `mode`, `vol:<0-100>`.
  - `11020000-...` (**Status**, Read / Notify): периодическая рассылка статуса: `track,position_ms,duration_ms,is_paused,playlist_size,volume`.
  - `11030000-...` (**Playlist**, Read / Notify): передача списка треков.
  - `11040000-...` (**Logs**, Read / Notify): текстовый поток логов.

### 3.4. HTTP REST API Master контроллера (Порт 80)
- `GET /player_status` — JSON статус плеера.
- `GET /playlist` — JSON массив файлов.
- `GET /player_cmd?cmd=...` — команды управления.
- `GET/POST /wifi_settings` — настройки сети в NVS.
- `GET/POST /sleep_settings` — настройки тайм-аутов сна в NVS.
- `POST /upload` — multipart/binary загрузка прошивки Master.
- `POST /upload_slave` — загрузка прошивки для Slave (транслируется по UART в реальном времени).

## 4. АЛГОРИТМЫ РАБОТЫ

### 4.1. Управление питанием и синхронный Deep Sleep:
1. Master отслеживает активность на CAN-шине.
2. При отсутствии пакетов дольше заданного тайм-аута (например, 30 сек):
   - Master сохраняет текущий трек, позицию в миллисекундах и источник в NVS.
   - Master останавливает звук и размонтирует USB.
   - Master опускает `GPIO 21` в **LOW (0V)**.
   - Slave видит `LOW` на `GPIO 34`, сохраняет состояние и уходит в `esp_deep_sleep_start()`.
   - Master настраивает пробуждение `esp_sleep_enable_ext0_wakeup(GPIO 15, 0)` и уходит в `esp_deep_sleep_start()`.
3. При появлении активности на CAN RX (`GPIO 15` LOW) Master просыпается, поднимает `GPIO 21` в **HIGH (3.3V)**, что пробуждает Slave. Воспроизведение возобновляется с сохраненного места.

### 4.2. Воспроизведение и переключение режимов:
- **Режим USB:** Чтение FATFS ➔ MP3 Decoder ➔ Программная громкость ➔ I2S0 Выход ЦАП. Автосохранение позиции каждые 60 секунд.
- **Режим Bluetooth (External Passthrough):** Чтение с I2S1 Slave RX (поток со Slave ESP32) ➔ Программная громкость ➔ I2S0 Выход ЦАП. Нажатия Next/Prev на руле отправляются в UART на Slave.

## 5. ТРЕБОВАНИЯ К АРХИТЕКТУРЕ КОДА

### Для Master (ESP32-S3):
Агент должен самостоятельно спроектировать модульную архитектуру:
- Точка входа: инициализация очередей FreeRTOS и запуск задач.
- Модуль звука: плеер USB (ESP-ADF), I2S Passthrough, софтверный регулятор громкости.
- Модуль CAN: драйвер TWAI, фильтрация ID `0x2D5`, антидребезг.
- Модуль питания: мониторинг бездействия CAN, сохранение NVS, Deep Sleep, ext0 wakeup, линия сна GPIO 21.
- Модуль связи со Slave: UART протокол (команды 0xAA и протокол OTA 0x55).
- Модуль BLE: BLE GATT сервер с таймером периодического Notify.
- Модуль сети: HTTP сервер, Web UI и REST API.

### Для Slave (ESP32):
- Точка входа: запуск стеков.
- Модуль Bluetooth: A2DP Sink, AVRCP, авто-подключение к последнему MAC-адресу из NVS.
- Модуль звука: настройка I2S Master Transmitter (GPIO 26, 33, 25).
- Модуль UART связи: прием команд Next/Prev и OTA прошивка через `esp_ota_ops`.
- Модуль питания: мониторинг GPIO 34 и переход в Deep Sleep.

### Для Android-приложения:
- Kotlin, Jetpack Compose, архитектура MVVM + Repository (с поддержкой переключения BLE / HTTP).
- Поддержка команды `mode` по BLE.
- Плавный прогресс-бар трека по данным BLE Notify.
